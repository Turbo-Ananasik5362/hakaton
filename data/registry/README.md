# Реестр проверенных фактов

Агент берёт профстандарты, коды трудовых функций, нормативные акты, литературу, издательства, ИИ-сервисы и версии
инструментов ТОЛЬКО отсюда. Всё, чего здесь нет, выводится с пометкой `[не подтверждено]`. Каждая запись — с URL
источника и датой проверки. GigaChat реестр не пишет и не дополняет. Модели записей — `app/core/registry_api.py`.

Все файлы — `{"items": [...]}`. Поля статуса у каждой записи: `"status": "verified"` (есть `source_url` и `checked_at`)
или `"to_verify"` (нельзя выводить без пометки; в `note` — что не подтвердилось).

| Файл | Что внутри | Важно |
|---|---|---|
| `norms.json` | Нормативные акты: `kind` (`federal_law`, `order`, `decree` — постановление или распоряжение Правительства, `letter`), номер, дата, **дословное** название, `applies_to` (`pk`, `dop`), `in_force`, `replaced_by` | Код выбирает акты по подстрокам названия («порядка организации и осуществления образовательной», «электронного обучения») — название не сокращать. У действующих актов `in_force_until` — срок действия. |
| `profstandards.json` | ПС: код, название, приказ действующей редакции, ОТФ и ТФ с кодами (`C/11.6`, буква латиницей) и **дословными** названиями, `tags` | Ключ `candidates_to_verify` — непроверенные кандидаты, загрузчик их не читает. `tags` — отдельные слова в нижнем регистре без «ё», в формах, которые встречаются в запросах («тестировщиков», «devops»): поиск ПС сравнивает их со словами запроса. |
| `ru_ai_services.json` | ИИ-сервисы: `available_in_ru` (false — стоп-лист), `aliases` латиницей и кириллицей, `kinds` | Алиасы ищутся по границам слова, к кириллическим допускаются падежные окончания; не добавлять алиасы-обычные слова. |
| `tools.json` | Инструменты: официальная документация (`docs_url`), `min_version` — минимальная поддерживаемая версия на дату проверки | Упоминание версии ниже `min_version` — ошибка проверки V29. Пороги устаревают: Kubernetes 1.34 — 27.10.2026, PostgreSQL 14 — 12.11.2026 (см. `note`). |
| `literature.json` | Книги (`book`) и документация (`doc`): авторы, точное заглавие, год, издательство, ISBN, `tags` | У каждой записи — слаг направления: python, data, ml, ai, education, security, networks, linux, devops, web, databases, testing, analysis, pm, digital. Выходные данные — только по каталогу РГБ/РНБ или сайту издательства, ISBN с верной контрольной суммой. |
| `publishers.json` | Издательства с `aliases` | Издательство каждой книги каталога должно находиться по названию или алиасу. |

Перед коммитом изменений реестра: `python scripts/check_registry.py` (код выхода 1 — есть ошибки) и `pytest -q`.

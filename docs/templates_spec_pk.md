# Спецификация шаблона: ДПП ПК (стажировка БСА, 248 ч)

Источник: `data/templates/pk_stazhirovka_bsa_248h.docx`, разобран через python-docx и XML (styles.xml, numbering.xml, tcPr), только чтение. Сверочная копия: `docs/case/sample_pk_stazhirovka_bsa_248h.md`.

Нумерация в документе:
- **P###** — индекс в `Document.paragraphs`, считая с 0. Абзацы внутри таблиц сюда не входят.
- **T#** — индекс в `Document.tables`.
- **body#** — индекс дочернего элемента `<w:body>`. В теле 234 элемента: 228 абзацев, 4 таблицы, 1 `bookmarkEnd` (body#113) и `sectPr` (body#233).

## 1. Общие параметры

### 1.1. Страница

| Параметр | Значение |
|---|---|
| Число секций | **1** (одна `sectPr` в конце тела, других `sectPr` в абзацах нет) |
| Альбомные секции | **Нет**, весь документ книжный |
| Размер | A4: 11906 × 16838 twips (21,0 × 29,7 см) |
| Поля | верх 1135 tw (2,0 см) · право 851 tw (1,5 см) · низ 1418 tw (2,5 см) · лево 1276 tw (2,25 см) · переплёт 0 |
| Колонтитулы | header/footer distance 708 tw (1,25 см). Частей header/footer **нет**: связей с ними в document.xml.rels нет, `titlePg` отсутствует |
| Нумерация страниц | **Нет**: нет полей PAGE и нет `pgNumType` |
| Ширина текста | 11906 − 1276 − 851 = **9779 tw (≈17,25 см)** |
| Прочее | `cols space=720`, `docGrid linePitch=360`, `defaultTabStop=708` |
| Оглавление | Нет |

### 1.2. Стили по умолчанию

- `docDefaults/rPrDefault`: **Times New Roman** (ascii/hAnsi/eastAsia/cs), **12 pt** (sz 24), язык ru-RU.
- `pPrDefault` пустой: интервал до и после 0, одинарный межстрочный, без отступа первой строки.
- **Normal** (`styleId="a"`) без собственных свойств, всё берётся из docDefaults.
- Абзацы с текстом расставляются вручную: выравнивание, `space_after` и bold заданы прямым форматированием (см. §3).

### 1.3. Разрывы страниц

Разрывы сделаны через `<w:br w:type="page" w:clear="all"/>` внутри run, а не через `pageBreakBefore`.

| Где | Как |

| P032 | Первый run абзаца с заголовком «1. ОБЩАЯ ХАРАКТЕРИСТИКА…», дальше идёт текст |
| P066 | Последний run абзаца «Удостоверение…» (конец раздела 1) |
| P114 | Пустой абзац с разрывом перед разделом 3 |
| P166 | Пустой абзац с разрывом перед «Приложение 1» |
| P185 | Пустой абзац с разрывом перед «Приложение 2» |

Специфика стажировки в целом:
- слова «В ФОРМЕ СТАЖИРОВКИ» на титуле;
- ЛК = ПР = ЛБ = 0 по замыслу, контактная работа 0 ч, всё уходит в СРС;
- «руководитель стажировки» в 2.5, 2.5.1 и 3.4;
- текущий контроль в форме «собеседования с руководителем стажировки»;
- срок в днях при режиме «до 4 часов в день» (62 × 4 = 248).

У обычной ПК без стажировки состав блоков тот же, но колонки ЛК/ПР/ЛБ заполняются.

## 3. Стили и форматирование

### 3.1. Используемые стили

В абзацах и таблицах встречаются только 5 стилей.

| Стиль (`style.name`) | styleId | Определение в styles.xml |
|---|---|---|
| Normal | `a` | Пусто: TNR 12, интервалы 0, одинарный |
| Heading 1 | `1` | bold, 13 pt (sz 26), до 16 pt (320), после 8 pt (160), `outlineLvl 0`. **Без `basedOn`** и без `keepNext` |
| Heading 2 | `2` | bold, 12 pt (наследуется), до 12 pt (240), после 6 pt (120), `outlineLvl 1`. Без `basedOn` и без `keepNext` |
| List Paragraph | `af3` | Пусто, без отступов |
| Normal Table | `a1` | Стиль всех 4 таблиц. Поля ячеек по умолчанию 108 tw, но в таблицах переопределены |

Heading 3–9 в styles.xml определены (цветные, Liberation Sans и т.п.), но **не используются**. Стиля Caption и подписей таблиц («Таблица N») в документе **нет**: таблица идёт сразу после заголовка подраздела.

### 3.3. Нумерация (numbering.xml)

| numId | abstractNum | Уровень 0 | Где используется |
|---|---|---|---|
| 1 | 2 | bullet «●», left 720 / hanging 360 | **Не используется** |
| 2 | 1 | bullet «–» (en dash), left 540 / hanging 360, `startOverride=1` | Все 50 списков в теле |
| 3 | 0 | bullet «–», left 360 / hanging 240, after 40 (2 pt) | 80 пунктов внутри ячеек T3 |

- Нумерованных (decimal) списков с numPr в документе нет. Все списки маркерные, все ilvl = 0.
- У маркера не заданы `rFonts`, поэтому он наследует шрифт абзаца.
- Все списки тела делят один numId=2. Для маркеров это не мешает.

## 4. Таблицы

Общее для всех 4 таблиц:
- стиль `Normal Table`;
- `tblBorders` single sz 4 auto, но **каждая ячейка переопределяет границы** через `tcBorders` single sz 1 цвета **AAAAAA**, то есть на практике тонкие серые линии;
- `tblCellMar` left/right 10 tw, но в каждой ячейке `tcMar` top/bottom 80 tw, left/right 120 tw;
- `tblLook` 0000;
- `tblLayout` и `jc` таблицы не заданы;
- первая строка с **`tblHeader`**, то есть повторяется на каждой странице;
- `cantSplit` нет;
- **vMerge нет ни в одной таблице**, объединения только по горизонтали (`gridSpan`).

## 7. Рекомендации для рендера

### 7.1. Что генерировать из модели данных

- **Титул**: название курса (1–2 строки в «ёлочках»), вид программы (флаг «в форме стажировки»), год. Реквизиты приказа всегда в виде `____`.
- **1.1–1.9**: тексты аннотации, цели (с перечнем ТФ списком), требований к слушателям, формы обучения. Объём (всего / контактная = ЛК + ПР + ЛБ / СРС / ИА / срок) **вычислять из учебного плана**, а не задавать текстом.
- **T0**: строки «ВД — ПК — опыт — умения — знания» из реестра профстандартов. Каждый пункт отдельным абзацем.
- **1.4, 1.5, 3.2.1**: профстандарт и коды ТФ только из `data/registry/profstandards.json`. Нормативные акты из справочника (273-ФЗ, № 266, № 816, ВК-1013/06 от 21.04.2015).
- **T1/T2/T3** строятся из одной модели «разделы → темы → виды работ (ЛК/ПР/ЛБ/СРС, часы, содержание)». Строки разделов, «Итоговая аттестация» и «Итого» **только вычисляются**, вручную не задаются. Метки «СРС (N часов):» в T3 формировать из того же числа, что и колонка часов. Аббревиатуру лабораторных работ выбрать одну (ЛБ или ЛР) и использовать везде.
- **Для стажировки** ЛК = ПР = ЛБ = 0 во всех строках, всё уходит в СРС. Текущий контроль идёт внутри СРС тем, а не отдельной строкой с нулями.
- **2.3**: срок, режим, при необходимости таблица по неделям или дням (в образце таблицы нет).
- **2.5.1, Приложения 1 и 2**: вопросы, критерии с баллами, порог «зачтено» — генерируются по курсу.
- **3.1, 3.2.2–3.2.5**: перечни ПО, литературы и ресурсов — генерируются по курсу, с ручной нумерацией «N. » в тексте.

### 7.2. Что брать как статичный шаблон (переформулировать своими словами)

- Шапка организации (3 строки, ОГРН/ИНН/КПП, адрес), «УТВЕРЖДЕНО», город.
- Все заголовки разделов 1–3, подразделов и «Приложение N» — фиксированный список из §2.
- Типовые абзацы:
  - 1.9 (удостоверение о ПК установленного образца);
  - вступление 2.5 (ТК + ИА, условие допуска);
  - 2.5.2 (ссылки на приложения);
  - 2.5.3 (анкетирование до и после обучения);
  - вводные фразы 3.1 про ЭО/ДОТ;
  - требования к доле практиков среди преподавателей в 3.4.
- Каркас Приложения 2: требования к проекту, детализированные критерии с диапазонами баллов, процедура защиты и порог 70%.

### 7.3. Технические подводные камни python-docx

1. **Стили.** Heading 1/2 в образце не имеют `basedOn` и шрифта. При генерации с нуля через `Document()` встроенные Heading будут Calibri Light с синим цветом. Варианты: использовать образец как базу (открыть копию .docx, очистить тело и сохранить `sectPr`) или явно задать стилям TNR, размеры и интервалы из §3.1. Шрифт задавать и в `w:eastAsia` (`rPr.rFonts.set(qn('w:eastAsia'), ...)`), иначе кириллица может уйти в другой шрифт.
2. **Заголовок раздела 1** делать стилем Heading 1, а не как в образце. Разрыв страницы ставить перед ним (`paragraph_format.page_break_before = True` или run с `WD_BREAK.PAGE`).
3. **Объединения.**
   - `cell_a.merge(cell_b)` создаёт `gridSpan` и сливает текст обеих ячеек в первую (остаётся лишний пустой абзац), поэтому текст писать **после** merge и чистить пустые абзацы.
   - Для T3 образец не использует vMerge (пустые ячейки кол. 0). Если делать вертикальное объединение темы, `a.merge(b)` по вертикали даёт `vMerge restart/continue`; это допустимо, но меняет вид относительно образца.
4. **Шапка-повтор.** python-docx не умеет `tblHeader` напрямую: добавить `<w:tblHeader/>` в `trPr` первой строки через `OxmlElement`.
5. **Ширины.** Надёжно ширина задаётся только одновременно в `tblGrid/gridCol` и в `tcW` каждой ячейки. Плюс `table.autofit = False` и, желательно, `tblLayout type=fixed`. Сумма ширин не больше 9779 tw. Ориентиры: T1/T2 = 9638, T3 = 9640.
6. **Заливка и границы ячеек** через XML: `w:shd w:val="clear" w:fill="F2F2F2"` (или E7E6E6). Границы ячейки — `tcBorders` single sz 1 цвета AAAAAA, либо одна `tblBorders` на таблицу (проще и даёт тот же вид). Поля ячеек — `tcMar` 80/120 или `tblCellMar` на таблицу. `vAlign center` для шапки.
7. **Списки.** python-docx не создаёт нумерацию. Варианты: база-документ из образца с готовыми `numId=2` (текст) и `numId=3` (ячейки), где пишется `numPr` (`ilvl=0`, `numId`) в `pPr`; или стиль «List Bullet» с переопределением маркера. Маркер «–» (en dash). Для нумерованных перечней (литература, нормативка, вопросы) образец использует ручной текст «1. », и так проще всего.
8. **Альбомных секций нет.** Если понадобится альбомная таблица (например, календарный график), добавить `doc.add_section(WD_SECTION.NEW_PAGE)`, поменять `orientation`, а `page_width`/`page_height` переставить вручную. Колонтитулы новой секции по умолчанию связаны с предыдущей (`is_linked_to_previous=True`).
9. **Колонтитулов и номеров страниц** в образце нет. Если решим добавить номер страницы, это поле PAGE через `fldSimple` или `fldChar` в footer; python-docx API для этого нет.
10. **Размеры шрифта в таблицах** задавать на каждом run, включая пустые ячейки и итоговые строки, чтобы не получить 12 pt, как в T1 R2. Числа выравнивать по центру единообразно во всех строках.
11. **Артефакты при работе от копии образца.** Не копировать highlight, color 333333, `lastRenderedPageBreak`, `proofErr`, `bookmarkEnd`.
12. **Проверка после рендера.** Перечитать .docx и сверить: Σ тем = раздел, Итого = Σ разделов + ИА = объём, T3 по теме и виду = T2, метки «(N часов)» = колонка, нет ЛК/ПР/ЛБ ≠ 0 у стажировки, P007 содержит `____`.

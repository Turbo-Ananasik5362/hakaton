# Спецификация шаблона: ДОП общеразвивающая (интенсив ИИ, 24 ч)

Сгенерированный `program.docx` содержит разделы программы и приложение № 1 по шаблону.
Отчёт автопроверки выдаётся методисту отдельным `report.docx` (ключ `files.report_docx`);
приложение № 2 с отчётом в программу не добавляется и V31 его не требует.

Источник: `data/templates/dop_intensiv_ai_24h.docx`. Разобран через python-docx 1.2.0 и чтение XML (`w:tcPr`, `w:numPr`, `w:sectPr`, `numbering.xml`, `styles.xml`).

**Как ссылаться на места в документе.** `[i]` — номер дочернего элемента `w:body`, то есть `list(doc.element.body)[i]`; таблицы тоже считаются. `P#` — номер в `doc.paragraphs`. `T#` — номер в `doc.tables`. Если `P#` не указан, его можно вычислить: `P = i − (сколько таблиц стоит выше)`. Таблицы находятся в `[95]`, `[101]`, `[108]`, `[185]`, `[192]`.

**Происхождение файла.** Документ экспортирован из Google Docs. На это указывают `customXML/item1.xml` (gDocsCustomXmlDataStorage), стиль `Normal` с именем `normal` в нижнем регистре, атрибуты `rsid="00000000"`, `w:sdt` с тегами `goog_rdk_*`, дробные значения twips (`12951.000000000002`, `282.9999999999999`, `100.0`) и `tblGridChange` в каждой таблице.

## 1. Общие параметры

### 1.1. Секции и страница

В документе 3 секции. Все разрывы типа «со следующей страницы» (`nextPage`).

| Секция | Границы в теле | Ориентация | Размер | Поля: верх / низ / лево / право | Колонтитулы (header/footer) | Особенности |
|---|---|---|---|---|---|---|
| 0 | `[0]`…`[92]` (sectPr в абзаце `[92]`) | книжная | A4, 11906×16838 twips (210×297 мм) | 1134/1134/1701/850 twips = 20/20/30/15 мм | 708 twips (12,5 мм) | `pgNumType start=1` |
| 1 | `[93]`…`[102]` (sectPr в абзаце `[102]`) | **альбомная** | 16838×11906 twips (297×210 мм) | 1701/851/1134/1134 twips = 30/15/20/20 мм | 709 twips | Поля «повёрнуты»: зона переплёта (30 мм) сверху |
| 2 | `[103]`…`[194]` (sectPr тела `[195]`) | книжная | A4 | 20/20/30/15 мм | 708 twips | — |

- Ширина набора: книжная страница 210 − 30 − 15 = **165 мм (9355 twips)**, альбомная 297 − 20 − 20 = **257 мм (14570 twips)**.
- В альбомной секции стоят только «2. Содержание программы», учебный план (T0) и учебно-тематический план (T1).

### 1.2. Колонтитулы и нумерация страниц

- Колонтитулов нет. У всех секций header/footer связаны с предыдущей (`is_linked_to_previous=True`) и пусты. Особый колонтитул первой страницы не включён.
- Номера страниц **не выводятся**: в секции 0 есть `pgNumType start=1`, но поля `PAGE` нет нигде (`fldSimple`/`instrText` = 0).
- Оглавления, сносок и закладок нет.

### 1.3. Значения по умолчанию

- `docDefaults` задаёт только `rPr`: `sz=28` (14 пт), `lang=ru`. В `pPr` есть только `spacing line=276 auto` (множитель 1,15). Интервалы до/после не заданы, то есть равны 0.
- **Шрифт по умолчанию не задан нигде**: нет `rFonts` ни в `docDefaults`, ни в стиле `normal`. Шрифты темы (Aptos / Aptos Display) нигде не используются. Явный `Times New Roman` есть только у части runs: абзацы `[35]`–`[38]` и все пункты списков с `numPr`. Остальной текст, в том числе титульный лист и таблицы, шрифта не имеет. Word в таком случае подставляет Times New Roman, другие приложения могут подставить другой шрифт. **В рендере шрифт нужно задать явно.**
- `fontTable`: Times New Roman, Georgia (не используется), Gungsuh (артефакт, см. §6).
- `settings`: `compatibilityMode=15`, `defaultTabStop=720`, `embedTrueTypeFonts=1`.

## 3. Стили и форматирование

### 3.1. Какие стили используются

- **Все абзацы тела и ячеек имеют стиль `normal`** (styleId `Normal`). Стили `Heading 1–6`, `Title`, `Subtitle`, `List Paragraph`, `Строгий1` объявлены, но не используются.
- Объявленный `Heading 1/2` — Times New Roman, не жирный, цвет `2E74B5`, 16 и 13 пт. Брать его как есть нельзя.
- Всё оформление задано **прямым форматированием** абзаца (`pPr`) и run (`rPr`).
- Стили таблиц `Table1`…`Table5` наследуются от `TableNormal` и задают только поля ячеек 0/10/0/10 twips. Границы и заливка заданы прямо в каждой таблице и ячейке.

## 4. Таблицы

У всех пяти таблиц общие свойства:

- `tblLayout fixed`, `tblLook 0400`, `jc=left`, без отступа слева.
- Границы: single, sz=4 (0,5 пт), чёрные, внешние и внутренние.
- Поля каждой ячейки (`tcMar`): сверху и снизу 60 twips (около 1,06 мм), слева и справа 90 twips (около 1,6 мм).
- **`tcW` нет**: ширины заданы только в `tblGrid`.
- `vAlign` и `trHeight` не заданы. У строк шапки `tblHeader=1` (повтор на каждой странице), у всех строк `cantSplit=0`.
- В каждой ячейке один абзац.
- Шрифт в ячейках не задан (кроме артефакта Gungsuh).

### 7.4. Технические подводные камни python-docx

- **Не брать этот файл как базу для `Document()`**: имя стиля `normal` в нижнем регистре, `doc.styles['Normal']` срабатывает только через устаревший поиск по style_id с предупреждением; Gungsuh, sdt, дробные twips, `tblGridChange`, `customXML`. Лучше чистый `Document()` или собственная очищенная база (в ней можно заранее определить numbering).
- **Шрифт задавать явно** в стиле Normal и в `docDefaults`: Times New Roman 14. `font.name` в python-docx пишет только `ascii`/`hAnsi`; `w:eastAsia` и `w:cs` нужно дописать через `rPr.rFonts.set(qn('w:eastAsia'), …)`.
- **Стили лучше завести свои**: текст (по ширине, 1,5, красная строка 1,25 см, до/после 0); заголовки (жирный 14 чёрный, без синего); текст ячеек (1,0, без отступа, 11–12 пт); шапка таблицы. Если для навигации используются `Heading 1/2`, их нужно перекрасить и снять размеры по умолчанию (в стандартном шаблоне python-docx это Calibri Light, синий).
- Если у Normal есть красная строка, **в ячейках её нужно обнулять**, иначе получится как в T1 и T3.
- **Альбомная секция**: `doc.add_section(WD_SECTION.NEW_PAGE)`, затем `orientation = LANDSCAPE` и **вручную поменять местами `page_width`/`page_height`**. Поля: 30/15/20/20 мм для альбомной, 20/20/30/15 мм для книжной. **Не ставить `add_page_break()` перед разрывом секции**, иначе появится пустая страница.
- **Ширины таблиц**: задавать и `table.columns[i].width` (gridCol, по нему ориентируется LibreOffice), и `cell.width` у каждой ячейки (tcW, по нему ориентируется Word). `table.autofit = False`, `tblLayout fixed`. Сумма не больше 9355 twips (книжная) и 14570 twips (альбомная).
- **Объединения**: `a.merge(b)` создаёт `gridSpan`/`vMerge`. Абзацы объединённых ячеек склеиваются, поэтому лишние пустые абзацы надо удалить и записывать текст после merge. Двухуровневая шапка T0: 4 вертикальных объединения слева, gridSpan=2 для «в т.ч.», 2 вертикальных справа.
- **Повтор шапки** (`w:tblHeader`), **заливка** (`w:shd fill=D9D9D9/EDEDED`), `cantSplit`, поля ячеек (`tcMar`) — API для них нет, только `OxmlElement`.
- **Списки**: python-docx не создаёт определения нумерации. Варианты:
  - базовый .docx с abstractNum («–» и decimal) и `numPr` в абзацах;
  - программно добавить abstractNum и num в `numbering_part`;
  - (хуже) набирать «– » вручную с висячим отступом.
- **Числа**: десятичная запятая («0,5»), целые без «.0», прочерк «—» для отсутствующих значений.
- **Чтение образца** (если понадобится): `paragraph.text`, `paragraph.runs` и `cell.text` **не видят текст внутри `w:sdt`**. Для `[116]` и T1 R14 C2 они возвращают `''`. Читать через `el.iter(qn('w:t'))`.
- Вертикальную разметку титула делать через `space_before`/`space_after` или фиксированное число пустых абзацев (в образце 4 / 5 / 13). Ни разрывы колонтитула, ни номер страницы на титул не ставить.
- Поля `____` — обычный текст в run, не поля формы Word и не элементы управления содержимым.
